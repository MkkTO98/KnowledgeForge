# Phase 2 Operational Guidance — Production Doctrine Freeze

Date: 2026-07-09
Status: operational guidance for KnowledgeForge Phase 2

## 1. Operating posture

KnowledgeForge should enter Operational Expansion.

Production families are now the primary development activity. Governance and architecture work are exceptional and should be triggered by production evidence, not by speculative improvement.

## 2. Default production-family planning stance

For each future family:

1. Assume the production doctrine is inherited.
2. Identify family-specific evidence scope and source identity.
3. Use the existing package model, validator model, provenance model, fingerprint model, reporting model, Production Support layer, and PEL governance.
4. Mature the family through the established family criteria.
5. Preserve rejected candidates.
6. Produce a family closeout report before Mature status.
7. Update PEL only with production evidence.

## 3. Phase 2 immediate direction

Follow the Phase 2 family order:

1. WDI Infrastructure annual-scalar evidence.
2. WDI Energy & Mining annual-scalar evidence.
3. WDI Agriculture & Rural Development annual-scalar evidence.
4. Broader WDI cross-family comparison.
5. WDI Trade annual-scalar evidence.
6. WDI Financial Sector annual-scalar evidence.
7. WDI Education or Health scale-family stress.
8. Deliberate non-WDI multi-source disagreement workstream.

Do not convert this order into a rigid campaign list. Each family still requires bounded planning before execution, but planning must inherit doctrine rather than redesign it.

## 4. Exceptional governance triggers

Pause ordinary production only if repeated production evidence shows:

- validator false positives or false negatives;
- package-contract insufficiency;
- provenance/fingerprint ambiguity not caused by malformed candidates;
- duplicate pressure exceeding campaign-local checks;
- family-closeout criteria becoming misleading;
- PEL failing to capture production pressure;
- sustained manual effort proving existing deterministic support inadequate.

## 5. Non-goals during Operational Expansion

Do not introduce:

- architecture redesign;
- methodology redesign;
- taxonomy redesign;
- validator redesign;
- package-contract redesign;
- runtime infrastructure;
- adapters/APIs/shared schemas;
- database coupling;
- repository coupling;
- local or frontier LLM generation.

## 6. Classification

This guidance preserves the agreed architecture and implements the doctrine freeze. It does not refine, duplicate, contradict, or drift.
